# Aerix — централизованная система тем Dark / Light

Ты — Senior QML/Quickshell Developer. Твоя задача — реализовать единую систему тем оформления Aerix, максимально используя существующую архитектуру проекта.

## 1. Архитектура

Сначала кратко изучи существующие Theme, Config и Appearance-компоненты.

- Если система тем уже существует — расширь и упрости её.
- Если отсутствует — создай минимальный QML singleton.
- Все компоненты должны получать цвета из одного источника правды.
- Избегай дублирования состояний, лишних сервисов и новых зависимостей.
- Сохрани существующую функциональность и расположение UI.

## 3. Разделение Status Bar и остальных glass-компонентов

**Status Bar** использует `glassBase`, `glassElevated`, `glassAlpha` и остальные цвета текущей палитры.

**Остальные glass surfaces** (Dock, Launcher, Popups, Media и другие) используют отдельные семантические токены:

| Токен | Dark | Light |
|---|---|---|
| `surfaceGlassBackground` | `#000000` | `#FFFFFF` |
| `surfaceGlassAlpha` | Сохранить текущее значение | Сохранить текущее значение |

Требование относится именно к фону стеклянных контейнеров, а не ко всем вложенным элементам.

Сохрани прозрачность, маски и совместимость с hyprglass. Не добавляй непрозрачные заливки поверх glass-эффекта.

## 4. Пользовательская конфигурация

Предусмотри возможность переопределять цвета извне, **без изменения QML-кода**.

Используй существующий механизм конфигурации. Если его нет — добавь один простой конфигурационный файл.

Пример желаемого поведения:

```json
{
  "theme": "dark",
  "dark": {
    "accent": "#FF8A65",
    "glassBase": "#202020",
    "surfaceGlassAlpha": 0.45
  }
}
```

Правила:

- Отсутствующие значения берутся из встроенной палитры.
- Некорректные значения не ломают интерфейс.
- Переключение `dark` / `light` централизованное.
- Все зависимые QML-компоненты реактивно обновляются.
- Не добавляй polling или отдельное чтение конфига для каждого виджета.
- Необязательно реализовывать hot reload файла на этом этапе.

## 5. Реализация

Выполни работу за три коротких этапа:

1. **Theme Manager:** адаптируй существующую систему или создай минимальную. Добавь обе палитры и пользовательские overrides.
2. **Интеграция:** подключи Status Bar и существующие glass-компоненты к новым токенам. Убери дублирующиеся определения цветов там, где они заменены.
3. **Проверка:** убедись, что обе темы работают, кастомные цвета применяются, QML не выдаёт ошибок, hyprglass и существующие интерфейсы не сломаны.

Не выполняй несвязанный рефакторинг. Не меняй компоновку интерфейса и архитектуру окон.

## Результат

После выполнения кратко сообщи:

- Какие файлы изменены.
- Где находится единый источник цветов.
- Как переключать Dark/Light.
- Как пользователь может переопределять палитру.
- Какие проверки прошли и какие не удалось выполнить.

**Главный критерий:** две работающие темы, единое управление цветами, внешняя кастомизация и минимальный объём изменений в кодовой базе. Не составляй отдельный план — сразу реализуй задачу.
