# Захват Background: исследование 2026-11-09

Статус: исследование, не реализация. Пользователь выбрал исследовать плагин;
изменения композитора, установка и загрузка требуют отдельного согласования.
Текущий WallpaperSource всё ещё читает awww; независимый захват не подключён.

## Проверенные ограничения

- `hyprctl -j layers`: обои сессии находятся в Background (уровень 0),
  Bottom (уровень 1) пуст. Адрес слоя из IPC не является источником ScreencopyView.
- Установленный Quickshell принимает монитор или toplevel, не layer-shell.
  Документация: https://quickshell.org/docs/v0.2.1/types/Quickshell.Wayland/ScreencopyView/
- Локальный `/usr/share/hyprland-protocols/protocols/hyprland-workspace-image-capture-source-v1.xml`
  содержит только `windows_only` и `everything`. Второй включает панели,
  pinned-окна и остальные слои, поэтому не заменяет захват чистого фона.
- В `/usr/include/hyprland/src/render/Renderer.hpp` есть `renderLayer`,
  `renderMonitorBackground` и framebuffer/context API. Это внутренние точки
  для исследования прототипа, а не стабильный публичный API захвата обоев.
  `getBackground` нельзя автоматически считать текстурой wallpaper daemon:
  встроенный фон Hyprland и внешние layer-shell поверхности различаются.

## Предлагаемый прототип (ещё не согласован к реализации)

1. Отдельный небольшой плагин, собранный под точную версию Hyprland.
2. По запросу overview отрисовать Background-поверхности нужного output
   в отдельный framebuffer. Не включать окна, курсор, Bar, Dock, overlay;
  Bottom не добавлять автоматически, поскольку там могут быть другие виджеты.

## Прозрачные окна в overview

`ScreencopyView` получает текстуру уже после обработки HyprGlass. Однако Dock
показал нужную деталь: `layer.enabled` с `OpacityMask` создаёт offscreen-pass
и сохраняет premultiplied alpha кадра. Overview теперь использует тот же путь;
в реальном кадре прозрачные Kitty-окна показывают Image обоев под ними, а не
экран за overlay. Простое прямое размещение ScreencopyView этого не делало.
Это решает текущий случай, но независимый источник обоев всё ещё нужен, если
будет убрана зависимость от awww.

Drag-копия больше не использует стеклянную карточку: для workspace берётся
только полотно с обоями/окнами, для окна — сама миниатюра; внешняя заливка
прозрачна. Это устраняет белую подложку независимо от протокола захвата.
3. Сначала экспортировать один уменьшенный снимок в приватный runtime-каталог
   с атомарной заменой. Quickshell читает результат и поколение снимка;
   код overview не знает названия wallpaper daemon.
4. Захват только пока открыт overview, без постоянного захвата полного экрана.
   Совпадающий фон output разделять между workspace; не создавать 10 копий.
5. Проверить прозрачные слои, scale/transform, смену output, отсутствие обоев,
   анимированные фоны, повреждение/обновление буфера и завершение daemon.
6. До загрузки в основную сессию проверить в отдельной тестовой сессии:
   ошибки плагина способны завершить композитор.

Нужно отдельно проверить ABI, корректную точку выполнения рендера, GL/Vulkan,
синхронизацию framebuffer и поведение уже загруженного hyprglass. Готовность
прототипа нельзя заключить только по наличию методов в заголовках.

Если сторонний скрипт меняет обои при переключении workspace, композитор видит
только текущий буфер output. Плагин не сможет восстановить фон неактивного
workspace без отдельного источника состояния; переключать workspace ради
снимка или показывать выдуманное состояние нельзя.

Официальный вход в разработку плагинов:
https://wiki.hypr.land/hyprland-plugins/development/getting-started/
